# Glossary

- **nSLOC:** normalised source lines of code, the usual audit sizing metric.
- **PoC:** proof-of-concept test demonstrating a finding.
- **Duplicate:** a contest submission with the same root cause as another.
- **Fix review:** verification that remediations address the findings.
- **Handler:** a contract that wraps calls for invariant fuzzing with bounded inputs.
- **Mutation testing:** injecting small code changes to check that tests detect them.
- **Safe harbor:** pre-agreed legal and operational terms for whitehat intervention.
- **Egress allowlist:** network policy that permits outbound connections only to named hosts.
- **Engagement letter:** the contract defining scope, timeline and data-handling terms for an audit.
- **Judge critic:** a prompt that argues why a draft finding would be invalidated under contest rules.
- **Known issues:** problems listed by the project before a contest, which are not eligible for rewards.
- **Precedent file:** a team record of past findings and agreed severities, used for consistency.
- **Trust boundary:** a point where data or calls cross from a less trusted to a more trusted component.
- **Worst-moment question:** "what breaks if this function is called at the worst possible time?"
